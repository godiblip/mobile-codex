# 에이전트 초대 (Claude·Gemini) 구현·기기 확인 안내

에이전트 초대 동작과 확인 범위를 설명합니다.

## 사용

1. 모든 대화는 기존과 같이 Codex와 시작합니다. 첨부, 파일·앱 선택기, 승인 방식, Fast 모드는 그대로입니다.
2. 입력창의 **+ → 에이전트 초대**에서 Claude, Gemini(Antigravity)를 1~2명 고릅니다. 에이전트마다 권한(**대화만**, **프로젝트 읽기**, **프로젝트 수정**)을 정합니다. 작업 폴더가 선택된 대화에서는 기본값이 프로젝트 읽기이고, 없으면 대화만입니다. 로그인되지 않은 에이전트는 **계정 연결**로 설정 화면을 엽니다. 새 대화에서 첫 메시지 전에 초대하면 첫 메시지와 함께 대화에 붙습니다.
3. 멘션이 없으면 모든 참가자가 같은 질문과 대화 기록을 받고 동시에 답합니다. 첫 응답이 도착한 순서대로 피드에 표시됩니다. `@codex`, `@claude`, `@gemini`(`@agy`, `@제미나이`), `@all`(`@모두`, `@전원`)로 일부만 부를 수 있습니다. `@claude`만 부르면 Codex 턴 없이 Claude만 답하고, Codex는 다음 차례에 그 내용을 읽습니다. 입력창에서 `@`를 누르면 참가자가 자동 완성 목록 맨 위에 나옵니다.
4. 답변 중 AI가 다른 참가자를 독립된 `@ID`로 부르면 현재 응답들이 모두 끝난 뒤 그 내용을 읽고 이어서 답합니다. 자기 호출, 중복, 이미 답한 참가자는 제외하며 호출 깊이 2, 한 메시지당 발언 9회로 제한합니다.
5. 에이전트가 답하는 동안 새 메시지를 보내면 진행 중인 순서를 끝내고 새 메시지를 처리합니다. 정지 버튼은 Codex 턴, 에이전트 답변, 대기 중인 순서를 모두 멈춥니다. Codex가 답하는 중의 메시지는 추가 지시(steer)로 전달되며, 다른 참가자의 진행 중인 답변과 자동 호출은 중지됩니다.
6. 상단의 **참가자** 버튼은 오른쪽 사이드바를 엽니다(휴대폰에서는 전체 화면). 이름을 누르면 모델·추론을 고를 수 있습니다. Codex 항목은 하단 모델 선택과 같은 값을 바꿉니다. 에이전트 항목에서는 권한·승인 방식 변경과 **대화에서 내보내기**도 할 수 있습니다. 내보낸 에이전트를 다시 초대하면 이전 세션과 읽은 위치에서 이어집니다.
7. 피드에는 그룹 대화의 각 답변 위에 말한 참가자의 이름과 아바타가 표시됩니다. 실패하거나 중단된 에이전트 답변은 그 자리에 이유가 표시되며, 다른 참가자는 계속 답합니다. 플로팅 대화는 같은 대화를 보여 주고, 에이전트 답변 앞에 이름을 붙입니다.
8. **설정 → 계정**에서 Claude Code, Antigravity(Gemini)를 설치·로그인합니다. **Linux 환경 설정**으로 앱 내 Linux를 설치·활성화한 뒤 **CLI 설치 / 업데이트**, **로그인**을 누릅니다. 표시되는 공식 링크를 브라우저로 열고 CLI가 요구하는 코드를 입력합니다. 로그인 입력은 화면 로그에 다시 출력하지 않습니다. 설치 질문은 y·n·방향키·Tab·Enter·Esc 버튼이나 입력란으로 답합니다.

## 구조와 문맥

| 경계 | 구현 |
| --- | --- |
| 대화 기록 | 기존 세션의 `messages`. 에이전트 답변은 `agent`, `agentName`, `status`를 가진 assistant 메시지 |
| 참가자·진행 순서 | `Engine.java`의 `GroupRun`, 순수 규칙은 `AgentGroup.java`(멘션·대상·문맥) |
| 에이전트 실행 | `AgentBridge.java` → 앱 내 Node `rooms/service.cjs` → `providers.cjs`, `provider-runtime.py` |
| 에이전트 도구 | `mobile-mcp.py`: 답변 중에만 유효한 로컬 인증 MCP. 권한은 Engine이 다시 검사 |
| 화면 | `web/agents-ui.js`, `agents.css`, `app.js`의 피드·자동 완성 |

세션에는 `agents`(참가자별 모델·추론·권한·승인 방식·공급자 세션 ID·읽은 위치)와 `codexCursorId`가 저장됩니다. 각 참가자는 자신이 마지막으로 읽은 메시지 이후만 받습니다.

- **Codex**: 기존 스레드를 그대로 사용합니다. 그룹 대화에서는 사용자의 입력 앞에 `[그룹 대화]` 문맥 항목을 붙여 다른 참가자 목록과 Codex의 마지막 답 이후 오간 메시지를 전달합니다. 화면의 사용자 메시지는 원문 그대로 보입니다. 처음 초대할 때는 그때까지의 대화를 Codex가 이미 본 것으로 표시합니다.
- **Claude·Gemini**: 처음 초대되면 지금까지의 대화 전체를 받습니다. 이후에는 마지막 성공한 턴이 입력받은 기록 이후의 메시지만 받습니다. 동시에 도착한 다른 참가자의 답은 다음 턴에 전달하며, 자신의 답은 네이티브 세션에 있으므로 다시 넣지 않습니다. 실패·중단된 턴은 읽은 위치를 옮기지 않으므로 다음 턴에 같은 메시지를 다시 받습니다. 완료되지 않은 다른 에이전트의 답은 전달하지 않습니다. 첨부 파일은 "Codex만 열람 가능"으로만 표시됩니다.
- 전달 문맥은 160,000자로 제한합니다. 넘치면 오래된 메시지부터 생략하고, 몇 개를 생략했는지 프롬프트에 적습니다. 자동 의미 요약은 하지 않습니다.
- Claude·agy 프로세스는 같은 참가자의 다음 턴까지 유지합니다. 공급자별 최대 두 개를 유지하고 5분간 쓰지 않으면 종료합니다. 다시 실행할 때 Claude `--resume <ID>`, agy `--conversation <ID>`로 이어갑니다.

## 권한과 실행

- **대화만**: 프로젝트·휴대폰 도구를 제공하지 않습니다.
- **프로젝트 읽기**: 대화의 작업 폴더에 대해 읽기·검색과 사용자가 활성화한 휴대폰 조회 도구만 제공합니다.
- **프로젝트 수정**: 참가자별 **승인 받기** 또는 **모두 허용**을 선택합니다. 기본값은 승인 받기이며, 수동 승인은 3분이 지나거나 중지하면 거절됩니다. 앱의 전역 읽기 전용 설정은 항상 적용합니다.
- **Claude 자동 검토**: 설치된 CLI가 지원할 때만 표시하고 `--permission-mode auto`를 사용합니다. MCP 도구를 미리 허용하지 않아 Claude 자체 검토를 거칩니다. 실행 시 실제 모드가 `auto`가 아니면 작업을 중단하고 해당 모델에서 선택지를 숨깁니다. CLI·계정 설정을 바꾼 뒤 준비 상태를 새로 확인할 수 있습니다. Antigravity에는 자동 검토 선택지를 표시하지 않습니다.
- 에이전트가 답하는 동안 참가자의 각 발언에 별도 도구 권한(lease)이 걸립니다. 이 동안 파일 편집·변경 복원·터미널 명령과 권한·설정 변경, 앱 업데이트 설치는 막힙니다. 응답 생성과 읽기는 동시에 진행하지만, 수정·명령·휴대폰 조작은 같은 프로젝트의 Codex 턴이 끝난 뒤 한 참가자씩 진행합니다. 승인은 정확한 도구·인자에 한 번만 유효하고 중지 시 취소됩니다.
- Claude는 기본 도구를 비우고 명시한 mobile MCP만 연결합니다. agy는 별도 에이전트·전용 설정과 파일·명령·URL 기본 도구 거절 규칙을 사용합니다. CLI 전체 자동 승인 옵션은 쓰지 않습니다.
- 승인한 `mobile_exec`는 선택한 프로젝트를 작업 디렉터리로 삼아 앱 UID의 셸에서 실행합니다. 60초·출력 1 MiB 제한과 프로세스 그룹 중지를 적용합니다. **작업 디렉터리는 OS 파일시스템 샌드박스가 아닙니다.** 승인 화면의 명령을 기준으로 판단해야 합니다. SAF 문서 폴더는 명령 실행을 지원하지 않습니다.
- Claude·agy 인증과 네이티브 세션은 Linux 내부의 공급자 전용 HOME에 저장됩니다. Linux를 삭제하면 이것도 삭제됩니다. 대화 기록은 앱 세션에 남으므로, 다시 로그인한 뒤 새 세션으로 처음부터 문맥을 받습니다.

CLI 설치는 패키지 목록을 강제 갱신한 뒤 전체 업그레이드와 의존성 설치를 함께 실행합니다(`pacman -Syyu`). 실패하면 CLI 설치로 넘어가지 않습니다. Claude 공식 설치 스크립트는 HTTPS curl로 받고 크기·시간·스크립트 헤더를 검사합니다. 공통 PTY 연결은 OSC 10/11/12 색상 조회와 커서·장치 조회에 응답한 뒤 제어 문자를 출력에서 제거합니다.

## 실기기 확인 절차

Android 10 이상 ARM64 기기에서 확인합니다.

1. 에이전트 없이 기존 Codex 대화를 확인합니다: 모델 목록, 스트리밍, 첨부, 추가 지시, 승인, 플로팅 대화.
2. Linux를 활성화하고 Claude·agy를 각각 설치·로그인합니다. 준비 상태에 실제 버전과 인증 상태가 표시되는지, 앱을 다시 시작해도 인증이 유지되는지 확인합니다.
3. 몇 번 대화한 Codex 대화에 Claude를 초대합니다. 앞선 대화의 고유 문자열을 Claude에게 물어 문맥이 전달됐는지 확인합니다.
4. Claude·Gemini를 함께 초대하고 멘션 없이 의견을 묻습니다. 모두 응답 중으로 표시되고 먼저 출력한 참가자부터 피드에 나타나야 합니다. 다음 질문에서는 이전 회차의 모든 완료 답변을 알아야 합니다. `@claude`는 Claude만 답해야 하며, 다음 Codex 턴이 그 대화를 알아야 합니다.
5. 참가자 사이드바에서 Claude 모델·추론을 바꾼 뒤 답변이 바뀐 모델로 실행되는지 확인합니다. 다른 모델로 대체되면 실패입니다.
6. 에이전트가 답하는 중에 정지, 새 메시지 보내기를 각각 시험합니다. 진행 중인 승인도 함께 취소돼야 합니다.
7. Claude를 로그아웃해 오류 상태로 만든 뒤 멘션 없이 보냅니다. Claude 답변에 오류가 표시되고 Gemini는 계속 답해야 합니다.
8. 테스트 프로젝트에서 읽기 권한 에이전트에게 변경·명령을 요청하면 모두 거절돼야 합니다. 프로젝트 수정·승인 받기에서는 승인 전에 변경이 없어야 합니다. 모두 허용과 Claude 자동 검토도 각각 확인하고, 둘에게 같은 파일 수정을 요청했을 때 작업이 겹치지 않는지 확인합니다.
9. 앱을 종료했다가 다시 열어 대화를 엽니다. 참가자·모델 선택이 유지되고 새 메시지만 전달되는지 확인합니다. 에이전트를 내보냈다가 다시 초대해 이전 세션에서 이어지는지 확인합니다.

## 검증 범위와 남은 제약

- Android 호스트 테스트(`AgentEngineTest`, `AgentGroupTest`)는 실제 `Engine.handle` 경로로 다음을 검사합니다: 초대 검증, 초안 초대가 첫 메시지에 붙는지, Codex 입력의 그룹 문맥, 멘션 전용 메시지가 Codex 턴을 건너뛰고 다음 Codex 문맥에 포함되는지, 정지·내보내기, 도구 권한 경계, 멘션·문맥 규칙. 주입한 CLI 이벤트로 동시 실행·응답 도착 순서·공급자 오류 격리·사용자 개입·수정 차례·승인 거절·재시작 후 문맥 및 설정 복원을 검사합니다. 실제 AI 응답은 아닙니다.
- Node 테스트는 실제 `service.cjs` 프로세스에서 가짜 CLI로 스트리밍, 세션 ID 보고, 중지, 설치 프로세스 정리를 검사합니다.
- 브라우저 검증(`tools/verify_agents_browser.cjs`, 320·390·1280px)은 초대 시트, 참가자 사이드바의 모델·추론 변경, `@` 자동 완성, 피드의 이름 표시, 내보내기, 계정 로그인 입력, 영어 전환을 확인합니다. 응답은 테스트 대역입니다.
- 연결된 Android 기기가 없어 실제 CLI 실행, 브라우저 인증 복귀, 실제 계정 모델과 AI 응답, 휴대폰 조작은 확인하지 못했습니다.
- 다른 대화를 보는 중에 에이전트가 `@codex`를 부르면 Codex는 이어서 답하지 않습니다. Codex 턴은 열려 있는 대화에서만 시작합니다.
- 이전 버전의 별도 "AI 대화방" 기록(`files/rooms/history`)은 새 화면으로 옮기지 않습니다.
